# 16A. OPTIONAL USER REGISTRATION AND GUEST USAGE FLOW

This section adds an optional account system for saving and managing documents. It does not change the permanent free-use business model or restrict access to PDF tools.

## 1. First Three Successful PDF Operations — No Signup

- Every visitor can use all available PDF tools without creating an account.
- Allow the user to complete their first **3 successful PDF processing operations** as a guest.
- Do not show an account creation popup before the third successful operation.
- Count only successfully completed PDF processing operations.
- Failed, cancelled or interrupted operations must not count.
- Reopening, previewing or downloading an already processed file must not count as a new operation.
- Persist the counter across page refreshes and browser navigation, using suitable local storage.
- Do not reset the counter daily.

## 2. Optional Account Creation Prompt After the Third Operation

Immediately after the user's third successful PDF processing operation completes, show a friendly, dismissible account creation prompt.

**Headline:** Keep Your PDFs Safe & Accessible!

**Description:** You've successfully processed 3 PDFs. Create your free account to save your documents, keep them organised and access them anytime.

**Benefits:**
- Save and organise PDF documents.
- Access saved documents from the account.
- Keep important files in one place.
- Manage documents more easily.
- Continue using every PDF tool for free.

**Primary CTA:** Create Free Account

**Secondary CTA:** Continue Without Account

**Additional message:** No OTP. No email verification. No phone verification. Creating an account is completely optional.

## 3. Never Block PDF Processing

This is a non-negotiable requirement.

- The third-operation prompt must never act as a paywall.
- Users can dismiss it and continue using every PDF tool.
- Users can continue processing PDFs without an account, without arbitrary daily or monthly task quotas.
- Do not introduce processing credits, tokens, forced registration or upgrade prompts.
- Never disable upload, editing, conversion, compression, download or any other PDF functionality because a user has not registered.
- Signup must never be required to download a processed PDF.
- If the user dismisses the prompt, do not show it repeatedly after every subsequent operation.
- Persist the dismissal preference locally and provide an unobtrusive way to create an account later.

The three-operation trigger is only an invitation to create an account for document saving and management. It is not a limit on free usage.

## 4. Registration Form

When the user selects "Create Free Account", display a simple registration form with:

1. Full Name
2. Email Address
3. Phone Number
4. Password

Requirements:
- Ask users to provide genuine and accurate information.
- Validate name, email format, phone number format and password requirements.
- Do not require OTP verification.
- Do not require email verification.
- Do not require phone verification.
- Do not send mandatory verification links.
- Never describe email addresses or phone numbers as verified.
- Use secure password hashing and established authentication practices.
- Keep personal information private and protected.
- Clearly explain how registration data and saved documents are used.

## 5. Guest-to-Registered User Experience

After successful registration:
- Redirect the user to their personal PDF dashboard.
- Offer an option to save existing guest-session documents to their account.
- Ask for explicit consent before transferring or uploading guest files.
- Do not automatically upload temporary guest files without permission.
- Allow users to upload, save, organise, rename, open and delete their saved documents.

## 6. Account Dashboard

Build a responsive dashboard containing:
- My Documents
- Recently Processed
- Saved PDFs
- Upload PDF
- Organise Documents
- Search Documents
- Rename Documents
- Delete Documents
- Account Settings
- Profile Information

## 7. Database and File Storage

- Guest PDF processing must work without creating a database record or requiring an account.
- Registered users need secure database records and private file storage for saved documents.
- Supabase Database, Authentication and Storage may be used if compatible with the existing architecture.
- Store user profile information and document metadata separately.
- Use private storage buckets and Row Level Security.
- Ensure users can access only their own documents.
- Never expose private document URLs publicly.
- Use secure temporary signed URLs when accessing stored documents.
- Provide a clear deletion mechanism for saved files.
- Do not promise unlimited cloud storage unless the infrastructure genuinely supports it.
- If a storage limit is reached, users must still be able to use all PDF processing tools. Only saving to the account may be affected, with a clear explanation.

## 8. Non-Negotiable Registration Rules

- First 3 successful PDF operations can be completed without signup.
- Show the optional account prompt only after the third successful operation.
- Unlimited daily PDF processing remains available to legitimate users, subject only to transparent technical constraints.
- Account creation is optional.
- No OTP, email verification or phone verification.
- No premium plans, paid features, subscriptions, credits, tokens, paywalls or forced upgrades.
- Registration is for saving and managing documents, not for unlocking PDF processing.

**Final UX principle:** Let users experience the product first. Invite them to create an account only after they have successfully used it. Never force registration or interrupt their ability to work with PDFs.
